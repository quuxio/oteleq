# Repository guidance

- If `~/.agents/AGENTS.md` exists, read it and follow the relevant guidance.
- Rust `compare-workload` compares repeated byte channels; `compare-observations` adds versioned typed boundary graphs and field differences. The embedded scalar generator implements plan/generate/run/replay/shrink/export-tests/clean with AST inventories for all eight languages, private paired execution and explicit blockers. Shrinking requires declared independent domains, preserves the original qualified failure and retains original/trial/final evidence plus a sealed replay suite. Generated scalar workers emit shared typed observations with explicit fixture expectations. Full semantic/build-aware adapters, richer object/factory codecs and action-scoped witness binding remain incomplete. Keep actual capabilities and design interfaces distinct.
- Use the `quuxio` GitHub account and credentials for all remote operations. Verify the API identity before each operation. Never use `stephenlclarke` credentials. Use `/opt/homebrew/bin/gh` directly on Stephen's Mac because other wrappers may override explicitly supplied credentials.
- The intended implementation uses a Rust core and language-specific adapters. Cover all eight current otelc language IDs: `c`, `cpp`, `rust`, `python`, `java`, `javascript`, `typescript`, `go`.
- Preserve application and dependency sources, build manifests and lockfiles. Generate tests, access helpers and private build copies in a new directory outside the target repository. Copying tests into the repository is an explicit user choice.
- Python regular source-package support is opt-in through ordered source-relative import roots. Preserve real module/source and selected-function binding; namespace, shadowed and ambiguous import contexts remain blockers. Do not infer installed-project metadata or imported-root coverage from a package caller.
- Declared Python/JavaScript/TypeScript plain receiver fixtures construct independently through existing constructors/functions. Preserve source/class/method identity, receiver and declared own-static roots, aliases/cycles and fixed construction inputs through replay/export/shrinking. Node captures source bindings in a private first static block, validates them around construction/calls and records own data descriptors; this is a diagnostic helper delta. Ordered Node receiver calls/release and bounded Node collection retain intermediate typed graphs. Node private storage, inherited/native storage and broader action sequences remain incomplete; do not imply general object support.
- Declared Java receivers use source-bound reflection helpers in both lanes for plain concrete source classes, including permitted private access. Preserve exact field/type/modifier bindings, primitive versus boxed identities, arrays, aliases and own-static roots. Reject foreign statics, inheritance/interfaces, opaque storage and access failures. Exception observations cover only exact supported class/message payloads. `java-observer-check` enforces compiled observer coverage; JaCoCo is confined to regression probes. See `docs/java-receivers.md`; general Java project/module integration and C/C++/Rust receiver routes remain incomplete.
- TypeScript explicitly freezes source/native emission. Collection and native-emitter targets require the actual public schema-2 config resolver before application launch; retain its request/response and each attempt's backend controls. Older unavailable profiles remain blocked. Preserve original class/creation/lifetime witnesses; private filenames do not declare capabilities.
- Account for every discovered function. Missing fixtures, unsupported constructs, incomplete state observation and unverified instrumentation are visible results, never successful skipped tests.
- Maintained fixed-fixture qualification must check complete independently expected values in every recorded repeat/lane. Cross-lane equality and partial raw tokens do not establish that the harness called the fixture with the intended arguments or returned its expected value. Use the declared codec, including float bits, UTF-16 units and Node argument bits.
- Standalone Rust defaults to the compiler backend. Opt-in LLVM uses separate matched flags and schema-2 builds, with profile1/inventory2 or profile2/inventory3 and schema-1 symbol resolution. Profile2 adds a fixed hashed frontend and selected compiler sysroot; uninstantiated declarations cannot witness a call. Metadata cannot select arbitrary executables or flags; do not relax the default manifest or witness contract to accommodate another backend.
- Original-source Rust compiler schema3 separately binds the fixed stable profile/MIR driver, original request and emitted inventory. Profile/schema substitution is refused. Its exact-revision corpus covers four generated scalar cases and separately curated semantic/aliased-module workloads, including complete future-registry health. Future owners can retain constructor and coroutine symbols; symbol counts are not invocation counts. General generated async, module, Cargo and receiver support remain incomplete. See `docs/rust-build-bundles.md`.
- Declared Go receivers bind existing same-package scalar factories through real go/types and a private observer package. Preserve complete source fields, addressable slots, package globals, aliases/cycles, fixed factory inputs and Go value-copy semantics. Float32 NaNs and unsupported storage refuse capture; never invoke application formatters. Actual-provider qualification is separate from plain worker tests. See docs/go-receivers.md.
- Go uses separate build-only and baseline/on replay APIs. Retain both real binaries, compiler channels and source/SDK/compiler/module identities, bind trace weaving/selection at build time and reject empty module graphs. Compiler and module caches live under the owned external go-cache directory; the application is never a cache location. Older combined compile/run providers require a new qualified provider.
- Describe outcomes as "equivalence over these tests and observations". Include test corpus, observation scope, source/build identity and gaps. Unit harness evidence is not evidence for a different shipping artefact.
- Run `make check` for documentation changes. Application implementation must add meaningful checks described in `docs/roadmap.md` and keep every affected document current.
