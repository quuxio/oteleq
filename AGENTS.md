# Repository guidance

- Explicit Go source-v1 receiver schedules use the original owned native monitor and private checkpoint package. Apply the first metric state before construction, require independent setters and advancing completed flush counters, retain every phase/acknowledgement and seal the host record's original bytes/file facts before final acceptance. Traces count all serial trees; metrics count only collection-enabled trees, including the factory under the initial state. Disabled windows and restored emission-off measurements need direct receipt. Raw generic health remains non-atomic; stronger paused checks apply only after the explicit flush barrier. Generated/retained qualification is separate from component coverage and broader Go admission remains open. See docs/go-metric-controls.md.

- Go readiness/checkpoint implementation belongs in the private `oteleq_generated_control` package. Application declarations may shadow builtins, types and constants; generated host-control code must not invoke them. Keep the import and whole private package in compiler-owned caller inputs, refuse reserved-path collisions (including dangling symlinks), and qualify changed helper recipes separately from frozen older workflows.

- Go compiler-only caller discovery must execute its fixed frontend from the attempt's owned `go-frontend` directory. Preserve that source and its file facts after Rust CLI temporary extraction is removed. Never replace an old missing temporary input or claim that newer durable retention recertifies historical receipts.

- Materialised Go callers require independent compiler/type discovery before SDK builds. Bind generated main and source-package identities, shifted target/factory declarations, exact active module source/embed/package denominators and the same compiler bytes. Preserve compiler/export-data file facts and metadata seals. Default build4 remains untagged. Explicit nonempty tags require the separate build5/inspection2 descriptor, caller-sealed canonical names, identical fixed compiler flags, complete command evidence and independently reconstructed excluded tooling pin. Component tag discovery does not qualify generated tagged execution. Component intents without caller discovery cannot claim this stronger binding.

- Go owned execution must bind actual kernel parent/group and complete fixed start records before releasing generated calls or constructors. Keep readiness/release private and bounded; retain both marker links through auditing to preserve inode facts. Use the shared runner's original deadlines/output limits/group cleanup. Successful exit/final SDK health is separate from direct OTLP receipt. Do not admit generated workflows or a new SDK build recipe from component checks alone.

- Rebuilt Go source-v1 explicitly uses untagged build4 or candidate tagged build5/inspection2, with config2/request1/plan1/prepared1/command1/execution1 and independent health4. Keep earlier build2/health3 and build3 evidence tied to its frozen source. Bind fixed compiler commands, caller-frozen original/SDK/context bytes, module settings and complete prepared records; never execute metadata-selected argv. Independently reconstruct the fixed call-only helpers/rules and exact private file denominator; rehashed changed helpers, extra source and reserved path/identifier collisions must refuse. Treat application/embedded-SDK identity separately from the supervisor. HTTP operation start/end/active counters remain separate from resource release and GC; unclosed bodies cannot pass final qualification. Preserve unavailable metric-point/trace-observer dimensions and censored object/resource counters. Use go_context.prepare before producer builds to reconstruct the complete 21-file no-task context from the pinned official bundle and fixed consumer extensions, never SDK renderers or producer outputs. Keep its attribution asset embedded and retained. Metadata/context/helper/health components do not admit public generated execution; workflow, receiver/live and retained-route qualification remain required. See docs/go-prepared-provider.md.

- Go snapshots, build intent/records and prepared caller/response values require canonical data seals as well as file checks. Capture caller intent before reading producer records and recheck it before reuse. Frozen dataclasses still contain mutable dictionaries; changing those dictionaries or repairing them after a file change cannot recertify an accepted record.

- Explicit Python prepared live schedules use owned private checkpoints and one unchanged application/SDK pair. The recorded 16-configuration origin/cache matrix covers Python 3.12/3.14 and all four initial metric states through generated and retained/promoted routes. Other providers/callable/build profiles need new qualification; component coverage alone cannot extend that scope. See docs/python-metric-controls.md.

Keep `cache-read` separate from `source-compiler`; a cache filename never proves compilation of current source. All observed cache roots need caller-owned inputs, including unexecuted roots.
