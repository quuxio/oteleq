# Complete input inspection

Planning and input guards refuse a directory that cannot be read or disappears during enumeration. An inaccessible subtree cannot become a successful partial source inventory, SDK identity, classpath catalogue or private snapshot seal. The CLI reports the input error and does not claim equivalence.

The same checked directory walk covers ordinary application snapshots, owned retained-bundle inspection, explicit Java source roots, Java dependency/build/class-output inventories, prepared Java SDK inputs and runtime archives, legacy SDK source trees, task SDK sources and decoder package identities. Private build checks also refuse an unreadable newly added source directory. Native post-discovery input errors retain `discovery-failure.json` and the partial workspace path.

Intentional exclusions remain in effect. A normal source walk still omits the documented build/cache directories; explicit Java generated-source roots are inspected when selected. SDK test directories outside the declared dependency identity are pruned before their contents are read. Symlink handling and file/byte budgets remain those of the selected caller or profile.

## Regular hash inputs

On qualified POSIX hosts, the shared content hasher opens input descriptors without waiting for a pipe writer, checks that the opened object is a regular file and only then reads its bytes. A named pipe cannot leave SDK/tool identity collection waiting for a writer. Permitted tool symlinks still resolve to regular files; callers which prohibit links keep their existing checks. Python task capture and Java build identities use the same hasher. Failed checks and reads close the owned descriptor.

This check does not provide an atomic snapshot or a general timeout for slow regular-file storage. Directory inventories, file-size budgets and source-preservation checks retain their separate scope.

## Resolve a refusal

Restore read and search access to the named input directory, or select a supported source/build context which excludes it explicitly. If a file tree changed during inspection, stop the writer and create a new plan. Workspaces and external reports remain available for inspection; cleanup also refuses private input trees it cannot verify. The tool does not change application or dependency permissions to obtain access.

This is an enumeration guard. It does not add semantic build inclusion, broader dependency/project integration, atomic filesystem snapshots or shipping-artefact qualification. The result remains **equivalence over these tests and observations**.

## Maintainer qualification

With a qualified legacy provider, its language tools and a normal POSIX account which cannot enumerate a mode-000 directory:

```sh
make generation-input-walks-otelc \
  PYTHON=/absolute/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/absolute/path/to/otelc \
  BEFORE_CLI=/absolute/path/to/pre-fix/quux-oteleq \
  REPORT_DIR=/absolute/path/to/new-input-proof
```

The maintained qualifier runs the full eight-language retained-source corpus, then checks unreadable original inputs, immutable snapshots, owned bundles and an explicit Java generated root. It retains old successful partial plans and new prelaunch refusals separately. Every temporary permission change is restored, and only its newly created fixture files are removed. Unit checks additionally exercise SDK/dependency boundaries, missing roots, directory disappearance, exclusions and private build inspection.

The [22 October qualification](qualification/input-inspection-2026-10-22.json) records 136 actual positive launches on runtime `6c61dcc`, 17 successful partial plans from the pre-fix CLI and 33 permission refusals before application launch. Four separate retained-bundle seal controls also refuse. Independent retained review checks all 20 reports, complete graphs, raw channels, witnesses and HTML/JUnit inventory accounting. All 7,360 recorded provider inputs, eleven links and eight tools remain unchanged. The full local gate passes 775 distinct regressions with 97.37% Rust product line coverage. This evidence is specific to the recorded POSIX host and frozen legacy provider.
