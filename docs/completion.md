# Project completion

The goal is to finish the application described in the [design](design.md) and [roadmap](roadmap.md), across all eight otelc languages. The delivered scalar generator is a foundation. Passing its maintained examples does not complete the broader project.

This checklist records the acceptance boundary. A row becomes complete only after implementation, negative controls, source preservation, current documentation and published exact-revision evidence cover the whole requirement. Optional features remain explicitly optional; unavailable requested capabilities remain visible.

Java now has an explicit [prepared SDK provider](java-prepared-provider.md) for the existing generated diagnostic workers, with compiler/launch/origin checks, actual PID and direct final health/decoded OTLP receipt. This advances runtime integration; broader live-control/context profiles, Java builds and remaining replacement-SDK language routes remain open. It does not complete any broader row by itself.

JavaScript and TypeScript also have an explicit rebuilt [source5/execution1 profile](node-source-context.md#rebuilt-sdk-source-profile), with [1,800-launch exact-revision evidence](qualification/node-source-provider-2026-10-22.json) for module formats, declared receivers, bounded collection, binary application output, file/HTTP effects and retained/promoted suites. Source/compiler/emission/body-entry and actual process/health/OTLP records are checked separately. [Live Node metric schedules](node-metric-controls.md) have separate [696-launch qualification](qualification/node-metric-controls-2026-10-23.json) for positive-first calls on Node 24/26 and both TypeScript compilers. The separate [2,784-launch startup qualification](qualification/node-startup-metric-controls-2026-10-23.json) adds all four initial states in the recorded JavaScript/TypeScript profiles, with 336 altered-evidence refusals and 720 independently recomputed comparisons. Invocation attribution, broader build/dependency graphs and shipping artefacts remain open; the full checklist below still applies.

Instrumentation and its generated bootstraps/extensions/probes must require no application or dependency coding changes. Users supply common configuration and build/launch setup. Live metric controls require one unchanged application process and build: collection and emission change independently and together, with actual collection suppression distinguished from exporter/network suppression and tracing verified unaffected.

Java [startup schedules](java-metric-controls.md#qualify-startup-schedules) have separate [2,256-JVM qualification](qualification/java-startup-metric-controls-2026-10-23.json) across stock, safe and archive prepared profiles and all four initial states. The corrected retained-only audit preserves original archive build-audit failures, checks every required route and revalidates 168 altered-evidence refusals plus 576 comparisons. It starts no new applications. This remains selected diagnostic workload evidence, with executed runtime and final cleanup compatibility identified separately.

Java [runtime archive integration](java-runtime-archives.md) now has an explicit generated project profile, an independent selected-JDK resolver, separate compiler/runtime catalogues, exact launch tooling and independently reproduced helper relocation. Its [260-JVM qualification](qualification/java-archives-2026-10-22.json) covers eleven archive variants, four same-process metric states, detached suites, scalar reduction and refusal controls. General build-system/module integration and shipping artefacts remain open.

Rebuilt [Python metadata negotiation and prepared runtime readers](python-prepared-provider.md) now have explicit selection, frozen installed-input/probe seals, independent request/command checks and process/journal/descriptor/health/OTLP accounting. A separate fixed-workload command exercises both lanes with independent application oracles. An explicit journal-2 reader independently checks declared read/root/execution/SDK relations and complete alias-preserving subgraph consistency as data. The generated profile remains blocked pending authentic selected-origin evidence in both lanes and its public capability qualification. These checks do not complete Python generated runtime integration or a broader requirement below.
