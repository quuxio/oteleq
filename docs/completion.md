# Project completion

The goal is to finish the application described in the [design](design.md) and [roadmap](roadmap.md), across all eight otelc languages. The delivered scalar generator is a foundation. Passing its maintained examples does not complete the broader project.

This checklist records the acceptance boundary. A row becomes complete only after implementation, negative controls, source preservation, current documentation and published exact-revision evidence cover the whole requirement. Optional features remain explicitly optional; unavailable requested capabilities remain visible.

| Requirement | Current evidence and remaining work |
| --- | --- |
| Source-wide callable accounting in all eight languages | Syntax inventories exist. Semantic/build inclusion, generic instances, inherited/private access and dependencies need project-aware adapters. |
| Actual project configuration | In progress: a validated, frozen policy for selection, inputs and execution budgets. Build, fixture and observation contracts must all be consumed by the application. |
| Real repository build/dependency integration | Rust has separate standalone compiler/LLVM recipes with matched flags and provenance checks. The [original-source schema3 corpus](qualification/rust-compiler-2026-10-20.json) adds 108 candidate-provider launches, explicit fixed future/alias semantics and 24 legacy compatibility launches; Cargo and general generated async/module integration remain open. The [qualified profile1/profile2 corpus](qualification/rust-frontend-2026-10-20.json) checks the fixed compiler frontend and emitted symbols for ordinary generated standalone callers. Python accepts explicit [regular source-package import roots](python-package-context.md), with real module/source binding and an [actual diagnostic corpus](qualification/python-package-2026-10-20.json); installed metadata, namespace packages and general dependency/build integration remain open. Go now has a [retained standalone build/replay boundary](go-build-bundles.md), with selected compiler/loaded-input identities and module preservation guards. Its [actual 78-launch corpus](qualification/go-builds-2026-10-20.json) covers generated suites, detached/fixed replay and refusal controls. Explicit [Go module/package context](go-package-context.md) adds active sibling files, real imports, semantic scalar types, private callers and frozen tags, with a [six-case/112-launch diagnostic corpus](qualification/go-packages-2026-10-20.json). Broader project integration remains open: compilation databases, Cargo targets/features, Go cgo/workspaces and build variants, Java classpath/modules and Node ESM/CommonJS/TypeScript project context. |
| Generated concrete inputs and domain fixtures | Scalar inputs, frozen concrete fixtures and declared independent scalar bounds/alphabets exist. Relational semantic domains, broader factories beyond declared Python/Java/JavaScript/TypeScript/Go receivers, complex arguments, richer reviewed preconditions and shared corpus materialisation remain open. |
| Constructors, receivers and mutable arguments | Python has [declared plain receiver fixtures](receiver-fixtures.md), using existing constructors/functions and independently reconstructed instance/own-static graphs, with an [actual five-case corpus](qualification/receivers-2026-10-20.json). JavaScript/TypeScript [qualified plain class fixtures](qualification/node-receivers-2026-10-20.json) add own-data/static descriptors and awaited method completion: 12 cases, 186 actual launches, generated/exported suites and scalar shrinking. [Java source receivers](java-receivers.md) add private field/method access, own-static roots and source/array alias graphs. Their [eight-case/151-launch corpus](qualification/java-receivers-2026-10-20.json) qualifies all four routes, scalar reduction and seven refusal controls on the recorded runtime/provider. Separate constructor/action targets, richer or external factories, mutable object arguments and [Go receivers](go-receivers.md) now implement same-package scalar factories and private source struct/array graphs, with actual-provider qualification pending. Receiver/access routes for C/C++/Rust and broader fixtures remain open. |
| Stateful, asynchronous and resource sequences | Fixed context/lifetime diagnostics exist. [Ordered Node receiver calls/release](ordered-sequences.md) add intermediate typed graphs and bounded Node collection observations (TypeScript has separate [264-launch emitter/provider evidence](qualification/typescript-collection-2026-10-20.json)), with [148-launch exact-revision evidence](qualification/ordered-sequences-2026-10-20.json). Arbitrary targets, yield/iteration/resource-close actions, broader schedules and the other runners remain open. |
| Typed observation and graph comparison | Generated scalar workers emit shared contracts/graphs across all eight languages. The [exact-revision diagnostic corpus](qualification/generated-typed-2026-10-19.json) qualifies the declared scalar/Python/Node scope, with initial-state, expected-error and alteration controls. Alias/cycle matching has core/compiler regressions. A [plain Python receiver corpus](qualification/receivers-2026-10-20.json) extends this to dictionary/own-static graphs and returned-receiver aliases. The [Node receiver corpus](qualification/node-receivers-2026-10-20.json) adds declared prototype/data descriptors, awaited completion and returned/static aliases. The [Java receiver corpus](qualification/java-receivers-2026-10-20.json) adds declared private field/array graphs and primitive versus boxed identity. Richer qualified object/factory codecs and cross-boundary identity remain open. |
| Configured globals/statics and instance roots | Existing scalar and Python/Node module roots are supplemented by Python receiver dictionaries and Node own-data receiver/static descriptors. Both retain declared own class data roots. Java adds declared private source fields and own-static roots through its [qualified reflection helper](java-receivers.md). Richer native/Java/Go/Rust objects, inherited/imported roots and explicit opaque/unobserved dimensions remain open. |
| Declared filesystem, fixture/network and resource effects | [Declared filesystem fixtures](filesystem-effects.md) reconstruct independent roots for all eight generated runners and capture bounded bytes, kinds and permissions. The [exact-revision diagnostic corpus](qualification/filesystem-effects-2026-10-20.json) completes 18 cases/544 actual launches, generated/exported suites, eight same-return file differences, two incomplete effects and all eight scalar reductions/replays. Scripted [HTTP fixtures](http-fixtures.md) implement bounded serial loopback requests/offered responses for all eight runners. Their [18-case/544-launch diagnostic corpus](qualification/http-fixtures-2026-10-20.json) qualifies generated/exported suites, eight same-return request differences, two incomplete controls and all eight scalar reductions/replays. General network protocols and resource effects remain open. Transient writes require a separate supported mode. |
| Matched baseline/on and declared off/fault lanes | Repeated baseline/on is implemented. Qualify the actual provider capabilities for disabled recording/export and optional exporter faults without substituting lanes. |
| Per-case instrumentation and transport witness | Actual local decoding exists. The [invocation-scoped witness proposal](action-witness.md) defines the producer/consumer rendezvous, context and compiler-probe requirements; it is not implemented. Extend qualification to each new callable/build/sequence and retain actual selection/transform provenance, health and loss counters. |
| Source/dependency preservation and private workspaces | Existing source/snapshot/ownership guards are tested. The [Go input guard qualification](qualification/go-inputs-2026-10-20.json) binds its module manifest/checksums and local runtime/policy sources, with changed-input refusal controls. Go retained builds also record loaded dependency/standard-library inputs and actual compiler/tool identities; general package graphs and SDK dependency isolation still need separate qualification. Extend preservation to every new build graph, third-party dependency fixture and promotion action. |
| Isolation, repeatability and resource budgets | Independent processes, configured time/output budgets and repeats, seeded scalar inputs and declared initial-state checks exist. CPU/memory limits, external fixture isolation and separately qualified container execution remain open. |
| Counterexample shrinking and replay | Frozen replay/export and deterministic scalar shrinking within explicit independent domains exist. The [exact-revision diagnostic corpus](qualification/shrinking-2026-10-20.json) covers 11 cases across eight languages and 472 actual launches, with generated suites, replay/export, witness controls and a visible float budget limit. Declared Python/Node receiver tests also retain fixed construction inputs while shrinking scalar method arguments. Relational/factory/object/action-sequence domains and shrinking remain open. |
| Inventory, observations and reviewable reporting | JSON evidence and standalone HTML/JUnit presentation expose case/inventory denominators, differences and strict gaps. The typed comparator supplies field differences; generated graph presentation retains contracts and field paths. Redaction/unobserved fields and richer per-capability statuses remain open. |
| Retained/promoted framework projects | External unittest/export exist. Complete the roadmap's independent framework projects, dependencies, dry-run promotion plans and explicit apply operations. |
| Actual production/shipping workload qualification | Open: exact artefact hashes, release recipes, managed transforms/loader provenance, representative workloads and independently recorded shipping observations. |
| Functional and performance gates | Functional scalar checks exist. Add independently reported application overhead/resource budgets and qualification for optional live toggles/fault scenarios. |
| Common eight-language and platform qualification | Scalar macOS ARM64 fixtures pass. The [integrated-provider corpus](qualification/integrated-provider-2026-10-20.json) checks the standard fixed/default/configured paths across all eight languages over 533 actual launches; optional profiles and richer capability/platform matrices remain separate. Extend the shared defect corpus to every new capability; qualify each published OS/architecture/toolchain combination through actual execution. |
| Installation, release and usable demonstration | Open: reproducible installation/release assets, dependency scanning and a real mixed-language application demonstration, including repeat execution and cleanup. |
| Review, CI, documentation and repository hygiene | Required protected checks exist. Every delivery must retain review, green final-head/main checks, current guidance and clean source/branches. |

The project is not complete while any required row is open or only partly qualified. The result remains **equivalence over these tests and observations**; exhaustive correctness of every possible input or schedule is not a deliverable.
