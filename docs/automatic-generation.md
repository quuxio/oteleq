# Automatic paired test generation

oteleq now inventories source files and generates an external `unittest` suite for C, C++, Rust, Python, Java, JavaScript, TypeScript and Go. The suite compares **equivalence over these tests and observations**. It is a bounded diagnostic check with a generated caller, not a proof about every function or a shipping artefact.

## Build and run

Build otelc and its qualified compiler/runtime adapters first. Use its locked CPython 3.12 environment so the OTLP protobuf decoder and Python adapter agree. Build oteleq with Rust 1.98.1 or newer:

```sh
cargo build --locked
export OTELEQ_PYTHON=/absolute/path/to/otelc/.venv/bin/python
OTELEQ_CLI=/absolute/path/to/oteleq/target/debug/quux-oteleq

"$OTELEQ_CLI" plan --source /absolute/path/to/application \
  --otelc-root /absolute/path/to/otelc --workspace-parent /tmp
```

`plan` prints the new private workspace path. Set `OTELEQ_WORKSPACE` to that actual path, then generate and execute:

```sh
OTELEQ_WORKSPACE=/tmp/oteleq-run-actual-id
"$OTELEQ_CLI" generate --workspace "$OTELEQ_WORKSPACE"
"$OTELEQ_CLI" run --workspace "$OTELEQ_WORKSPACE" \
  --report-dir /absolute/path/to/new-report

# The retained suite uses Python's standard unittest framework for every language.
"$OTELEQ_PYTHON" "$OTELEQ_WORKSPACE/tests/test_equivalence.py"
```

The report directory must be new and outside the application, otelc and workspace. Generation never edits the application, its dependencies, manifests or locks. Workspaces remain available until explicit cleanup; there is no automatic deletion after a successful run.

The CLI embeds its adapter sources, so an installed binary does not depend on an oteleq source checkout. It still needs the selected Python environment, otelc build and language tools. Keep the same CLI and tool contents for replay; changing them requires a new plan. `cargo install --path . --locked` installs the CLI locally.

The generated suite remembers the CLI path used during generation. If the same binary is moved, export `OTELEQ_CLI=/new/path/to/quux-oteleq` before running the suite; its content identity must still match the plan. `OTELEQ_PYTHON` selects the qualified adapter-host environment. See the [command/flag reference](cli-and-configuration.md#implemented-commands) and [actual workspace layout](test-generation.md#current-workspace).

Path flags accept both `--source PATH` and `--source=PATH` forms. Use full option names; abbreviated options are rejected. Input repository boundaries are checked before extracting embedded workers.

## Selection and inputs

All recognised files are inventoried by default. Use repeated `--language ID` to select a subset; the report records that selection. `--exclude 'qualified.pattern'` explicitly excludes matching function identities. Free entrypoints named `main`, Java static `void main(String[])` methods and native declarations without a source body are inventoried as excluded callers/declarations. Nested or instance methods named `main` remain blockers. Exclusions remain visible. No selected unsupported function becomes a passing skipped test.

Up to three distinct concrete scalar inputs per function are generated by default (`--cases 1` through `--cases 1024` changes the budget). The [project policy](#project-policy-and-concrete-fixtures) can set that budget and freeze explicit domain cases. Integer inputs start with `0`, `1`, `-1`; unsigned inputs use nonnegative values. Booleans, floats and supported strings have their own deterministic pools. Edges remain first; larger budgets add seeded finite scalar samples. Multiple parameters use shifted pools rather than an exhaustive Cartesian product; duplicate concrete inputs are removed. Finite domains such as booleans can yield fewer cases than the budget. C/C++/Rust attempts build only the lane being executed. Go retains a matched baseline/instrumented build pair, then launches the requested lane without compilation. Zero-argument functions have one case. JavaScript and unannotated Python parameters receive bounded scalar samples; those samples do not establish business preconditions or useful domain coverage.

The implementation supports synchronous accessible free functions, Java static methods, declared receiver methods and qualified Node async functions. Python/Node can observe supported returned objects and objects reachable through declared module globals/arguments. Native, Java, Rust and Go state capture supports accessible scalar globals. Declared [Java receiver fixtures](java-receivers.md) also capture supported source fields and own-static roots through a fixed reflection helper. [Go source receivers](go-receivers.md) additionally retain declared private struct/array slots, pointer cycles/interior aliases and package-global rebindings. Their its [actual-provider corpus](qualification/go-receivers-2026-10-20.json) completes 168 launches. User-selected exclusions can narrow the run to that supported scope.

Separate constructor targets, general receiver factories, nested callables, generic instantiations, pointer/buffer inputs, Rust Cargo features, multi-file native builds and broader Go build recipes, Python async/generator schedulers and arbitrary dependency fixtures need further adapter work. They remain named blockers or retained build failures. The policy supports explicit finite scalar argument cases. Declared plain Python/Java/JavaScript/TypeScript receiver fixtures and [Go source receivers](go-receivers.md) are supported as described below; general object factories and build recipes remain unimplemented; unsupported fields are rejected.

Go can use explicit [module roots and build tags](go-package-context.md) for actual package/type discovery, sibling files and private library/`main` callers. Supported named scalar types keep their real observed type labels. Initialisers and inactive host/tag/test files remain explicit blockers when selected as targets.

Static-language observers use restricted codecs. Rust formats only canonical primitive and standard string/unit implementations, refusing application `Debug` or `to_bits` methods even when a source type shadows a primitive name. Go reads primitive reflection values without calling `Stringer`, `GoStringer` or custom formatters; unsupported values terminate the worker outside application panic recovery. Files declaring `panic` or `recover` functions need a separate fixture and remain blocked. Java uses fully qualified bootstrap helpers and observes only final primitive wrappers/strings; unknown object formatters and exception message overrides are refused. Its message codec accepts exact `Exception`, `RuntimeException`, `IllegalArgumentException`, `IllegalStateException`, `NullPointerException`, `ArithmeticException`, `IndexOutOfBoundsException`, `ArrayIndexOutOfBoundsException`, `StringIndexOutOfBoundsException`, `UnsupportedOperationException`, `ClassCastException` and `NumberFormatException` classes from `java.lang`. Other exception classes need a qualified codec. A codec failure is incomplete evidence, never a matching application error or observed equivalence.

## Project policy and concrete fixtures

Pass `--config /absolute/path/to/equivalence.toml` to `plan`. The [example policy](../examples/equivalence.toml) is executable. Unknown keys, unsupported schema/language IDs, duplicate selectors/cases and unsafe limits fail validation. A policy is at most 1 MiB. CLI `--language` and `--cases` override the corresponding policy values; CLI exclusions extend the policy exclusions.

```toml
schema_version = 1
languages = ["python"]

[functions]
include = ["api.calculate"]

[generation]
seed = 42
cases_per_function = 8

[limits]
case_timeout_ms = 5000
baseline_repeats = 3
instrumented_repeats = 3
max_capture_bytes = 262144

[[fixtures]]
language = "python"
source = "api.py"
function = "api.calculate"
cases = [[7], [41]]
```

Source and function selectors are case-sensitive globs over complete POSIX relative paths and qualified function identities; exclusions win. Source selectors limit discovery, while the immutable snapshot retains the regular application inputs needed by existing private builds. `excluded_files` and excluded language IDs remain in the plan. Qualified function identities are available in an initial `plan.json`; create a new plan after configuring their fixtures.

Each fixture replaces automatic inputs for its matched callable(s). `source` defaults to `**`; optional `language` scopes a fixture when a shared policy is narrowed with CLI language selectors. Multiple matching fixtures are an error. A fixture matching no inventoried callable is an error, including its partial workspace path for inspection. Arguments must have the correct arity and supported scalar types; integer range checks reject narrowing. Cases retain both requested values and the concrete target representation (including binary32/binary64 rounding); duplicate cases after conversion are rejected. Go floating inputs are constructed from their exact IEEE bits; an untyped Go `-0.0` constant would otherwise lose its sign. No application observations are normalised. Plain native `char` currently uses the portable 0..127 range; explicitly signed/unsigned byte types have their declared ranges. Current native ranges describe host builds, not cross-compilation. Complex objects/buffers still require the unfinished factory contract.

A successful baseline return is the default fixture expectation. Matching unexpected exceptions/panics are blocked rather than accepted as equivalent. Declare an intentional error explicitly in its concrete fixture:

```toml
[[fixtures]]
language = "python"
function = "api.expected_failure"
cases = [[0]]
expected_baseline = { kind = "error", category = "exception", type = "python.builtins.ValueError" }
```

Use category `panic` for Rust/Go. The type is the captured error/payload type, such as `rust.panic.str`, `go.string`, `java.lang.IllegalArgumentException` or `cpp.std::runtime_error`. Inspect the retained typed bundle before choosing that contract. An expectation is a reviewed input requirement; it is never inferred from matching lanes. It does not waive exact stdout/stderr, state or instrumentation checks. Unequal known starting state blocks the comparison; missing or unstable state remains incomplete.

The resolved policy, exact typed cases and a policy digest are frozen into the owned plan and retained reports. An external policy edit does not change a frozen suite; export carries the resolved policy without requiring its original file. Editing a policy inside the application changes the source snapshot identity and requires a new plan.

Rust provider selection is explicit and frozen in the same policy:

```toml
[adapters.rust]
backend = "compiler"
```

`compiler` is the default standalone-source backend. `llvm` selects the separate compiler-hook profile and schema-2 build contract. The consumer verifies fixed profile/SDK/plugin paths and hashes, compiler-resolvable SDK dependencies, the selected compiler's actual verbose version, its complete argument recipe, original declaration coordinates, resolved symbol and exact target/startup selection before application launch. Missing, changed or unsupported evidence fails the run; there is no silent backend fallback. Other backend names and adapter settings are rejected. Earlier compiler captures retain their original identities and do not qualify LLVM.

The [original-source compiler schema3 contract](rust-build-bundles.md) separately binds a fixed stable compiler profile, MIR driver, original request and emitted-instance inventory. Its [exact-revision corpus](qualification/rust-compiler-2026-10-20.json) completes 96 generated/exported scalar launches, 12 separately curated fixed launches and 14 retained-record refusals against candidate `aca9d5a`, plus 24 legacy compatibility launches against `0419a51`. A present original-source profile cannot substitute a legacy schema1 build. Original-source attempts require an empty future registry with admission available independently of drained traces. Existing frozen provider evidence remains unchanged. The generated caller is still standalone and synchronous; fixed future/alias diagnostics do not enable general async or module generation.

The LLVM profile is a bounded `target/debug/otelc-rust-llvm.json` beside the provider adapter, with its SDK under `target/rust-llvm-sdk/debug` and the compiler pass under `target/debug`. `OTELC_RUSTC` must select that profile's compiler; the stable compiler used to build oteleq can be different. Profile and manifest data cannot choose arbitrary executables or compiler flags. The current LLVM contract is standalone, synchronous source only: Cargo/features, multi-source compilation, generics, asynchronous execution and other contexts require separate adapter work and qualification.

Profile schema1 requires inventory schema2. Profile schema2 instead requires inventory schema3 and the fixed regular `target/debug/otelc-rust-frontend` asset with `frontend_sha256`. The frontend is frozen with the other provider inputs. This recipe adds exactly `--sysroot` pointing at the selected compiler's installation; `build.compiler.program` still identifies that compiler. Build schema2, resolved schema1 and the four compiler-hook hashes remain unchanged. Mixed profile/inventory versions, metadata-selected paths and altered recipes are refused.

Inventory3 records strict `compiler_name`, `compiler_expansion`, `compiled_symbol` and `emitted` fields. The supported generated target and independent startup each need one unique emitted symbol matching the actual resolution and their ordinary compiler owner name. An uninstantiated declaration has `emitted=false` and an empty symbol; it cannot provide a runtime witness. Macro-expanded targets and multiple generic instances remain outside the generated scalar caller's qualified scope. The consumer retains the selected compiler name and frontend hash in build evidence. Spans remain name-based; these records do not authenticate an individual invocation or add probe IDs. Unit acceptance of this format is separate from qualification against an immutable producer.

The [20 October record](qualification/rust-frontend-2026-10-20.json) qualifies the final profile1 foundation and repaired profile2 frontend using consumer runtime `4db9bb9`. Both retain the expected unstable-panic gap; the profile2 run also rejects four additional rehashed compiler-provenance edits. The failed expression-macro closure predecessor is retained separately. These are ordinary generated standalone callers, not consumer generation of macro targets or generic instances. The producer frontend contract is developed in [otelc PR72](https://github.com/quuxio/otelc/pull/72); its own full gate and release status are separate.

Repeats range from 2 to 32 per lane. `case_timeout_ms` bounds each application launch (1 to 900000 ms); build/tool deadlines remain separate. `max_capture_bytes` limits accepted combined application stdout/stderr and typed observation bytes (1 to 262144). The total corpus remains capped at 1024 cases. Limits never convert incomplete capture or a failed instrumentation witness into a pass.

## Discovery and build boundary

| Language | Inventory | Generated execution |
| --- | --- | --- |
| C/C++ | Clang AST JSON | Private include driver; matched LLVM 22 compilation and otelc pass |
| Rust | Pinned `syn` syntax AST | Private appended driver; actual rustc and otelc Rust adapter |
| Python | Standard `ast` | Independent CPython caller and actual otelc monitoring adapter |
| Java | JDK `JavacTask` Tree API | Private javac classes plus separate JVM caller and actual agent |
| JavaScript/TypeScript | otelc's pinned TypeScript compiler AST | Private appended Node caller and actual loader; matched TypeScript baseline emission |
| Go | Standard `go/parser` AST | Private appended same-file caller, retained Go build pair and compiler-free baseline/on replay |

C/C++ scalar spellings are scoped to those languages. Other languages' names such as `i32`, `float64` and `String` do not establish a native primitive: unresolved native aliases are visible fixture/type blockers. Generated native callers also use compiler type checks on parameters, returned values and observed globals before permitting raw scalar reads. Structured values and unsupported floating representations cannot be compared through object padding. Broader canonical alias resolution remains part of semantic/build-aware discovery.

These are syntax inventories. Compilation and runtime witnesses qualify individual runnable cases; syntax alone does not establish semantic types, build visibility or safe domain inputs. Parse/tool errors produce inventory blockers even with function filters. An unmatched fixture after failed discovery retains `discovery-failure.json` in its unsealed partial workspace. Native C/C++ AST output has a separate 64 MiB compiler-metadata bound; application process output retains its 4 MiB bound. Rust requires otelc's separate standalone-source artefact API (`rust --build SOURCE.rs --output-dir BUNDLE`, then `rust --run BUNDLE`). The compiler candidate contract is [otelc PR65](https://github.com/quuxio/otelc/pull/65); the opt-in LLVM profile/resolution contract is [otelc PR68](https://github.com/quuxio/otelc/pull/68). Providers which expose only combined compile-and-run are unsupported. Cargo build-only is not qualified.

The [integrated-provider corpus](qualification/integrated-provider-2026-10-20.json) separately checks consumer `2e3e056` against frozen otelc `d6d03b7`: 24 default cases across eight languages, 38 configured cases, retained framework/export replay and explicit mutation/binding/fixture controls, alongside standard fixed and Rust-only diagnostics. Fixed qualification now checks complete independently expected typed results and every concrete Node argument, rather than partial tokens or cross-lane equality alone. The recorded 533 launches do not qualify richer receiver/effect/shrinking corpora, optional profiles, shipping artefacts or another producer revision.

Dependencies must already be available to the qualified local tools; generation does not install them into the application.

Python supports an explicit [regular source-package context](python-package-context.md) through `[adapters.python] import_roots`. Private source roots preserve relative imports, package initialisers and `src` layouts under their actual module names. Namespace packages and ambiguous/shadowed targets are blocked; installed-project metadata, dependency installation and imported-module observation remain outside this capability.

Python, Java, JavaScript and TypeScript also support [declared receiver fixtures](receiver-fixtures.md) for ordinary methods on plain classes. A fixture names an existing constructor or factory (a same-class static method for Java) and scalar construction arguments; every lane independently reconstructs the receiver. Source bindings, own declared class roots, instance graphs, aliases/cycles and fixed construction inputs remain bound through replay/export and scalar method-argument shrinking. Other receiver/build/storage contexts remain unsupported.

Go requires the separate [retained build/run API](go-build-bundles.md), not the former combined compiler/launcher. Provider identities include `adapters/go/go.mod`, `go.sum` and the runtime/policy Go source trees. Each retained bundle additionally binds the selected compiler/tool hashes and environment, loaded source/dependency bytes, both real executable hashes and resolved module graphs. Changed, added or missing recorded inputs invalidate execution. The private compiler/module caches under `go-cache/build` and `go-cache/modules` are reused across attempts in that workspace; export/derived workspaces own separate caches. Cache files do not themselves establish project build coverage. General Go package/build integration, SDK dependency isolation, workspaces and project cgo remain open.

Java uses `-Xshare:off` in both lanes. C/C++ select fixed LLVM 22 locations or explicit `OTELC_CLANG`/`OTELC_CLANGXX`; metadata verifies the canonical selected directory. Set qualified `OTELC_RUSTC`, `OTELC_NODE`, `OTELC_JAVA` and `OTELC_GO` where defaults are unsuitable. Rust SDK/compiler distributions and Node native observer ABI must match. Both Rust lanes use the same source-relative pathname and caller-selected recipe: `--edition=2024 -O -g` for `compiler`, with `-Zmir-enable-passes=-Inline,-ForceInline -Ccodegen-units=1` added for `llvm`. Build stdout/stderr stay in build evidence; application capture uses a no-build launch. The consumer rejects a changed flag/manifest contract and verifies executable, retained plan, entry source, SDK and adapter hashes plus compiler provenance. LLVM additionally verifies the profile/plugin, inventory and resolution records. Metadata never selects executable paths. See [tool qualification](eight-language-capture.md#run). Each exact-revision record names its platform/provider; an earlier macOS ARM64 capture does not qualify another backend, Linux or Windows.

## What is compared

Every case runs at least twice without instrumentation and at least twice with telemetry enabled (or the configured repeat counts), in separate processes and independently copied writable projects. The same frozen inputs and harness bytes are used in both lanes. Source, snapshot, corpus, generator, CLI, Python/decoder and tool identities are checked; changed identities fail. Helpers are excluded by exact function selection.

Bundle artefact digests aggregate the frozen source, case harness and qualified tool/adapter contents. They do not hash every output emitted by a runtime compiler or loader. Available native build binaries have separate retained hashes; shipping-artefact qualification remains outside this result.

The comparator checks exact application stdout/stderr and shared typed return/error and before/after graphs. Python graph observations retain own dictionary field order, reference aliases, cycles, arbitrary-size integers and float bits. Node observes plain objects/arrays through own data descriptors, preserving property order, prototype category, extensibility, aliases, sparse-array properties, bigint and float bits; accessors, symbols and unsupported prototypes are incomplete observations. Opaque observer failures are not converted into application exceptions. Python exception graphs retain arguments, custom fields and causal links; Node observes supported Error own fields and excludes stacks. Exception traceback/stack objects and Java/C++ extra exception fields are outside scope; unrecognised native panic/error payloads fail capture.

Native workers record actual compiler byte order, primitive widths, char sign and IEEE format before decoding scalar values; object padding is not a codec. Rust's closed primitive trait and Go reflection report actual value tags; pointer-sized widths come from the worker. Java final wrappers preserve their runtime types and UTF-16 units. The shared representation uses decimal strings for integers and exact hexadecimal float/string units, retaining signed zero, NaN payloads and unpaired Java/Node surrogate units. Static arguments remain passed by value; arbitrary mutable argument factories remain unimplemented. Declared plain Python/Java/Node receiver fixtures are separate from that argument contract.

Each case retains `bundle.json` with raw worker channels for inspection and `typed-bundle.json` for its actual comparison. Every launch also retains `typed-observation.json` beside its original observation. Raw state serialisation is not an exact application byte channel in typed comparison: local node labels do not establish object equality. The shared graph matcher checks field values, aliases, cycles and declared initial roots. Typed payloads plus stdout/stderr must fit the configured capture budget; a case bundle is capped at 16 MiB. An oversized bundle fails with retained evidence rather than a truncated pass.

C++ message observation is limited to exact `std::exception`, `runtime_error`, `logic_error`, `invalid_argument`, `domain_error`, `length_error`, `out_of_range`, `range_error`, `overflow_error` and `underflow_error` types. Other exception types and subclasses fail capture before their virtual `what()` accessor is called; an application-defined accessor is not a passive codec. Extra fields and general exception fixtures remain unsupported.

The shared JavaScript/TypeScript observer identifies supported errors by their known prototype identities without reading a potentially overridden `name` getter. Accessor and proxy state is refused without evaluating it. Replacement of the observer runtime builtins remains outside qualification.

Python reads ordinary instance dictionaries through their builtin descriptor and builtin exception storage. It refuses overridden dictionary/exception descriptors, custom metaclasses, invalid class identities, hidden slots, extra native member/getset storage, builtin container bases and non-string object-field names without running their getters or comparison callbacks. Exceptions such as `OSError` and `UnicodeDecodeError` need additional field codecs. Arbitrary extension descriptors and slot/private access require separately qualified fixtures. Observed class labels and own dictionary fields do not prove class origin, class-level behaviour or hidden extension state. Object IDs are local to each captured graph; cross-boundary replacement, weakref and finalizer effects remain outside this contract. This does not qualify application code which replaces observer/interpreter builtins.

[Ordered Node receiver calls/release](ordered-sequences.md) retain each intermediate boundary and can detect state changes restored before the final call. Node collection uses explicit bounded test controls; [TypeScript source/native emitters](typescript-collection.md) additionally require a frozen backend and public provider capability gate. Collection that is not observed and incomplete lifetime telemetry remain inconclusive.

Global roots are source-declared top-level assignments/variables. [Declared filesystem roots](filesystem-effects.md) add independently seeded before/after byte channels across all eight runners. Imported-module state, hidden fields, arbitrary receivers, undeclared filesystem/network effects, mutation-and-reversion between boundaries and concurrent schedules are outside this observation scope. Those limits appear in the evidence. This version does not implement an instrumented-off lane. [Automatic scalar shrinking](counterexample-shrinking.md) requires explicit independent domains and preserves the qualified failure; object/sequence shrinking remains open. Retained JSON reports can be presented as [standalone HTML and JUnit XML](reporting.md).

Telemetry is decoded separately. An ordinary single-call instrumented invocation must contain exactly the selected function identity and one complete root tree, with valid IDs/parent graphs, matching service/scope, zero loss/pending counters and finished export. Recursive span counts and escaping-error counts are runtime observations, not independently predicted call counts. Repeated counts must agree. A baseline that exports telemetry, missing instrumentation, missing observations, crashes, timeouts, output overflow, unstable repeats or source changes cannot pass.

Before importing Python application code, the driver compiles the frozen source without executing it and retains the selected function's code identity. Before calling it, the driver requires an ordinary function with the same code, source location and module namespace. Dynamic rebinding, callable proxies and replaced bodies fail capture; a span emitted by a startup call cannot qualify a rebound replacement. Startup calls that add extra selected root trees remain incomplete under the current witness contract. General action-scoped telemetry attribution for constructed fixtures and sequences still needs provider support.

For JavaScript/TypeScript function declarations, the parser selects a binding-capture position after any hashbang and directive prologue. The driver retains the hoisted declaration before application statements execute and refuses a changed binding before invocation. These access helpers are explicit diagnostic source deltas; they do not qualify arbitrary dependency initialisation or context propagation. An unchanged startup invocation that adds selected roots still cannot pass the ordinary one-root witness. Declared sequences instead require the requested number of independent method roots and the selected source factory root when collection needs a creation link.

Node's graph encoder and runner live in a separate generated module, so ordinary application bindings named `Map`, `Object` or `JSON` cannot replace observer helpers. Synchronous results are not implicitly awaited; only a declared async function receives an await boundary. Global mutation of runtime builtins remains outside qualification.

Source snapshots are capped at 10,000 files, 8 MiB per file and 256 MiB in total. Symlinks and non-regular files in the selected snapshot are rejected. `.git`, `target`, `node_modules`, `.venv`, `__pycache__`, `build` and `dist` are excluded and recorded; functions in those directories are outside the inventory. `.h` defaults to C; C++ headers use `.hpp`, `.hh` or `.hxx`. Recognised JSX/TSX can still require unsupported runtime/build context. Generation is capped at 1,024 cases. Workers have a wall-time limit and a 4 MiB combined captured stdout/stderr limit, and their process group is killed on completion/failure. Application stdout/stderr plus the state/outcome observation must fit within 256 KiB per attempt. Python/Node graphs are bounded at 512 nodes and depth 32. A denied process-group cleanup signal is accepted only when a bounded OS process listing confirms that no live members remain; live groups or unavailable verification fail the run. This is trusted local execution, not a hostile-code sandbox.

## Reproduce the qualification

With all qualified otelc tools available, this runs the maintained eight-language scalar fixture, exercises the generated framework and exported replay, then checks that a changed global object is detected while the function return remains identical:

```sh
make generation-otelc PYTHON=/absolute/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/absolute/path/to/otelc REPORT_DIR=/tmp/new-generation-qualification
```

The fixture covers 24 matching cases/96 paired-control launches, eight generated framework cases, exported replay and three deliberately different state cases. It also checks rebound callables, refused static observer callbacks, three explicit fixture/initial-state controls and two Node helper lexical-shadow cases. It is diagnostic evidence with the declared observation scope. No original application/source tree is modified.

The [19 October typed-worker record](qualification/generated-typed-2026-10-19.json) binds these results and the 38-case/228-launch configured corpus to runtime revision `162ae7c`, its frozen CLI and the immutable private provider candidate. Raw and typed Unicode alteration controls are rejected. This qualifies the declared diagnostic scope on macOS ARM64; richer object/build contexts, the [proposed invocation-scoped witness](action-witness.md), shipping artefacts and other platforms remain open.

The Rust split-path qualification preserves real unused-function build warnings separately from exact application stderr, checks u128 extrema, f32/negative-zero representation and `file!()` logical paths, and rejects deliberately altered retained stderr:

```sh
make generation-rust-otelc PYTHON=/absolute/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/absolute/path/to/otelc REPORT_DIR=/tmp/new-rust-build-qualification
```

This is a Rust-only standalone-source check; it does not establish a common eight-language provider revision.

To exercise the opt-in LLVM profile, select its exact compiler and pass the explicit backend to the same qualifier:

```sh
OTELC_RUSTC=/absolute/path/to/profile/rustc \
make generation-rust-otelc PYTHON=/absolute/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/absolute/path/to/otelc REPORT_DIR=/tmp/new-rust-llvm-qualification \
  GENERATION_ARGS='--backend llvm'
```

This covers six matching cases/36 launches and a deliberately unstable panic case/six launches, with three repeats per lane. The stable panic fixture installs its own application hook with independently expected stderr. The unstable fixture retains changing process/native-thread output and must remain incomplete under exact byte comparison; the strict whole-application gate therefore exits `3`. Its hook closure remains an explicitly excluded helper requiring a separate capture fixture. This is not whole-inventory equivalence. Actual decoded instrumentation and both raw/typed altered-stderr rejection are required. The LLVM qualifier also rejects altered retained compiler/profile/plugin/inventory/resolution/selection records, including rehashed semantic edits. Those metadata controls do not execute the target again. Only a completed exact-revision qualification record establishes the tested compiler/profile combination.

The [19 October Rust LLVM record](qualification/rust-llvm-2026-10-19.json) binds that result to consumer runtime `b824b0b` and private provider `6da80fbb`/CLI `ce8e1a0`. It also retains the separate default compiler, common 24-case/96-launch and configured 38-case/228-launch results. Exact source/binary/profile identities and the earlier incomplete corpora remain distinct; an experimental profile result does not qualify a shipping artefact.

The configured-policy qualification adds concrete domain cases, three repeats per lane, integer extremes and lossless UTF-16 strings, plus an altered-observation rejection control:

```sh
make generation-policy-otelc PYTHON=/absolute/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/absolute/path/to/otelc REPORT_DIR=/tmp/new-policy-qualification
```

## Reports, replay and retention

[`render-report`](reporting.md) creates private HTML/JUnit presentations from this retained JSON without executing the application. Incomplete or untested inventory entries remain errors, including in partial replay reports.

`report.json` retains every case result, the complete selected/excluded/blocked inventory, source identity, observation scope and source-preservation result. Case directories retain the concrete corpus, generated source, build logs and hashes, launch vectors, raw application observations, runtime reports, OTLP protobuf/HTTP records, comparator bundle and JSON comparison. Partial results remain available if a later case fails.

Exit `0` requires nonzero completed cases and no selected blockers. `1` reports a reproducible difference; `2` reports argument errors or a blocked fixture/initial-state contract; `3` reports incomplete evidence or an unresolved inventory blocker; `4` reports a tool/build/protocol/identity failure. Mixed results give precedence to `4`, `2`, `3`, then `1`. The generated `unittest` suite turns every selected blocker into a failing test.

`run` qualifies the complete selected inventory. `replay` qualifies only the requested frozen case and writes its new report under `workspace/runs/replay-*`. The generated suite replays each runnable case and separately fails selected blockers. Both invocations consume the policy already frozen by `plan`; there is no `--keep-workspace` flag: workspaces are always retained until explicit cleanup.

```sh
"$OTELEQ_CLI" replay --workspace "$OTELEQ_WORKSPACE" --case case-id-from-corpus

# Inspect the copy plan, then explicitly retain a portable bundle.
"$OTELEQ_CLI" export-tests --workspace "$OTELEQ_WORKSPACE" \
  --destination /absolute/path/to/new-tests
"$OTELEQ_CLI" export-tests --workspace "$OTELEQ_WORKSPACE" \
  --destination /absolute/path/to/new-tests --apply

"$OTELEQ_CLI" clean --workspace "$OTELEQ_WORKSPACE"
```

Export copies the frozen application snapshot, tests, corpus, plan and instructions into a new destination. The exported suite runs against that snapshot and retains its original provenance. It can be incorporated into an application's repository by choosing a new subdirectory explicitly; it does not silently rebind tests to future application changes. Create a new plan to test changed application code. The destination refuses overwrites. Retained/generated boilerplate is MIT licensed; copied application source retains its own licence, and the oteleq implementation remains AGPL-3.0.

Cleanup requires the ownership marker and refuses unknown top-level files or edited snapshots/suites. Private snapshot/suite checks include cache/build directories as well as source files; added files there remain preserved when cleanup refuses. Set `PYTHONDONTWRITEBYTECODE=1` when importing generated tests through another runner. Keep reports independently before cleanup. A retained workspace is not a guarantee that external toolchains or dependencies will remain available.

## Qualify native scalar type guards

make generation-native-otelc PYTHON=/path/to/otelc/.venv/bin/python \
  OTELC_ROOT=/path/to/qualified/otelc REPORT_DIR=/tmp/oteleq-native-types-new

This C/C++ diagnostic checks six primitive cases with independent value oracles and retains two deliberately unsupported object aliases and compiler-declared constructors as blockers. Its tested application therefore exits the strict generation gate with `3`; the qualification script succeeds only when all six supported cases match with actual instrumentation and unresolved aliases cannot pass. This is not whole-inventory equivalence. Compiler regressions separately refuse object results, globals and implicit constructor arguments even if malformed metadata bypasses inventory validation.
